# คู่มือการใช้งานทุกหน้า

[สารบัญคู่มือ](README.md) · [EEG และข้อมูล](eeg-and-data.th.md) · [แก้ปัญหา](troubleshooting.th.md)

## 1. เตรียมเครื่องและบัญชี

สำหรับรับ EEG ใช้เบราว์เซอร์ที่มี `navigator.bluetooth` และเปิดผ่าน HTTPS หรือ `http://localhost:3000` หน้าเว็บตรวจ secure context และ Web Bluetooth ก่อนเชื่อม การใช้งาน Dashboard โดยไม่รับ EEG ไม่ต้องมีเครื่อง Muse

เตรียมเครื่อง Muse ที่ใช้ Classic protocol เปิด Bluetooth ของคอมพิวเตอร์/อุปกรณ์ เปิด Muse และปิดแอปอื่นที่อาจกำลังเชื่อมเครื่องเดียวกัน เช่น แอป Muse ในมือถือ สวมเซนเซอร์ตามวิธีของโครงการก่อนตรวจคุณภาพสัญญาณ

การขอสิทธิ์วิจัย/ดูแลระบบให้ติดต่อผู้ดูแลฐานข้อมูล ฟอร์มสมัครไม่มีตัวเลือกสิทธิ์พิเศษ

## 2. สมัครสมาชิกและเข้าสู่ระบบ

### สมัครบัญชีผู้ใช้ทั่วไป

1. เปิดหน้าเว็บ เลือก Register/สมัครสมาชิก ถ้าผู้ดูแลเปิดการสมัครไว้
2. กรอกชื่อ อีเมล รหัสผ่าน และยืนยันรหัสผ่าน ชื่อปล่อยว่างได้ แต่ยาวไม่เกิน 80 ตัวอักษร
3. อีเมลถูกตัดช่องว่างหัวท้ายและแปลงเป็นตัวพิมพ์เล็ก Server รับอีเมลยาวไม่เกิน 254 ตัวอักษร
4. รหัสผ่านต้องยาว 8–200 ตัวอักษร และช่องยืนยันต้องตรงกัน
5. กดสมัคร ระบบสร้างบัญชี `user` และ session แล้วตรวจบัญชีผ่าน server อีกครั้งก่อนเปิด Dashboard

กรณีอีเมลซ้ำจะขึ้นข้อความว่าอีเมลถูกใช้แล้ว หากไม่มีปุ่มสมัครหรือแสดงว่าระบบปิดการสมัคร ให้ขอบัญชีจากผู้ดูแล ค่าเปิด/ปิดมาจาก `REGISTRATION_ENABLED` ไม่ใช่สิ่งที่ผู้ใช้เปลี่ยนเองได้

### เข้าสู่ระบบและคืน session

1. เลือก Sign in กรอกอีเมลและรหัสผ่าน
2. ระบบตรวจ password hash และเพิ่มตัวนับ login ฝั่ง server เมื่อตรวจผ่าน
3. เปิด Dashboard พร้อมชื่อและประเภทบัญชีในแถบบน
4. เมื่อโหลดเว็บใหม่ ระบบลองคืน session จาก cookie และตรวจว่าบัญชียังอยู่ในฐานข้อมูล

Session อายุสูงสุดเจ็ดวัน การกด refresh ไม่ใช่การ login ใหม่ จึงไม่เพิ่มตัวนับ `login_count` ฝั่ง server เสมอไป หากเปลี่ยน secret, cookie หมดอายุ หรือบัญชีถูกลบ ต้อง login ใหม่ ไม่มีหน้า Forgot password หรือการเปลี่ยนรหัสผ่านใน UI ปัจจุบัน; ผู้ดูแลใช้ขั้นตอนใน [บทฐานข้อมูล](database-admin.th.md)

Login จำกัด 10 คำขอต่อหนึ่งนาทีต่อ IP bucket และ Register จำกัด 8 คำขอต่อหนึ่งนาที เมื่อเกินจะได้รับ `429` พร้อม `Retry-After` ให้รอก่อนลองใหม่

## 3. เมนูและการใช้งานทั่วไป

| เมนู | หน้าที่ |
| --- | --- |
| แดชบอร์ด | ข้อมูลรวมสำหรับ staff หรือข้อมูลรอบในเครื่องสำหรับบัญชีทั่วไป |
| ห้องทดลอง EEG | เตรียมชุดทดลอง ตรวจ Muse บันทึก EEG และจัดการรอบที่เก็บในเครื่อง |
| ภารกิจการรู้คิด | พื้นที่เกมและแถบลำดับสามเกม ฝึกเกมนอกการบันทึก |
| ประวัติแบบประเมิน | ประวัติจากเครื่องมือประเมินเดิมใน localStorage |
| ผลสรุปและเปรียบเทียบ | ทางลัดไปตารางสรุปผลใน Dashboard |
| ส่งออกข้อมูล CSV | ทางลัดไปหน้าสรุปซึ่งมีปุ่มส่งออก ไม่ได้เริ่มดาวน์โหลดทุกไฟล์ทันที |
| ผู้ดูแลระบบ | แสดงเฉพาะ admin ใช้ปรับการตั้งค่าและค้นสรุปรายรหัส |

กดปุ่มเมนูบนมือถือเพื่อเปิด/ปิด sidebar หรือย่อ sidebar บนจอใหญ่ ปุ่มภาษา EN/ไทยเปลี่ยนภาษาและจำไว้ในเบราว์เซอร์ ชื่อ CSV คีย์ JSON และค่าที่บันทึกไม่เปลี่ยนตามภาษาหน้าจอ

ช่องค้นหาบนแถบบนพากลับ Dashboard เมื่อเริ่มพิมพ์ Staff ใช้ค้นชื่อ อีเมล หรือรหัสผู้เข้าร่วมในรายการโปรไฟล์ บัญชีทั่วไปใช้ค้นรหัสผู้เข้าร่วม รหัสรอบ หรือกลุ่มของรายการในเครื่อง กด × เพื่อล้างค่า ปุ่ม refresh ในแถบบนเรียกโหลดข้อมูล Dashboard ใหม่ ไม่เท่ากับการ reload เว็บทั้งหน้า

อย่าสลับไปทำงานอื่นระหว่าง Task; การออกจากหน้าเกมหรือซ่อนแท็บจะทำให้รอบหยุดก่อนครบตามกลไกรักษาเวลา

## 4. Dashboard สำหรับนักวิจัยและ admin

ทั้งสอง role ใช้สี่แท็บเหมือนกัน เปลี่ยนแท็บได้ด้วยเมาส์ หรือปุ่มลูกศรซ้าย/ขวา Home และ End เมื่อ focus ที่แท็บ

### 4.1 ภาพรวม

ภาพรวมอ่านโปรไฟล์ทุกบัญชีจาก server รวมบัญชีที่ไม่มีรอบทดลอง ใช้ตัวกรองประเภทบัญชีและกลุ่มวิจัยร่วมกับคำค้น ผลที่กรองใช้กับกราฟและรายการผู้ใช้

| ตัวชี้วัด/กราฟ | วิธีคำนวณ |
| --- | --- |
| จำนวนบัญชี | จำนวนบัญชีที่ตรงตัวกรอง ไม่ใช่จำนวนผู้เข้าร่วมที่ไม่ซ้ำ |
| บัญชีที่มีรหัสผู้เข้าร่วม | นับโปรไฟล์ที่ `participantId` ไม่ว่าง รหัสซ้ำไม่ถูก deduplicate |
| อายุเฉลี่ย | เฉลี่ยเฉพาะอายุที่บันทึกถูกต้อง 10–120 ปี ไม่ใช้ 0 แทนช่องว่าง |
| ประเมิน MMSE ครบ | มีระดับการศึกษาและคะแนนครบด้านที่ต้องใช้ |
| สัดส่วนกลุ่ม | `patient`, `control`, และยังไม่ระบุ |
| ช่วงอายุ | 10–39, 40–59, 60–79, 80–120; อายุว่างไม่เข้าช่วงใด |
| ระดับการศึกษา | ไม่ได้เรียน ประถม สูงกว่าประถม และยังไม่ระบุ |
| ผล MMSE รายบัญชี | คะแนนรวมเทียบคะแนนเต็มของระดับการศึกษา 23 หรือ 30 |

กราฟ MMSE ไม่แสดงแบบประเมินที่ยังกรอกไม่ครบ และไม่มีการแต่งค่าทดแทนข้อมูลที่หาย กราฟแสดงสูงสุดแปดบัญชีแรกที่ประเมินครบในรายการที่กรอง กดปุ่มดู/แก้ไขในแถวผู้ใช้หรือแท่ง MMSE เพื่อเปิดฟอร์มผู้ใช้ มีรายการตัวอย่างสูงสุดหกบัญชีและปุ่มไปดูทั้งหมด

### 4.2 ผู้ใช้: ค้นหาและแก้โปรไฟล์

1. เปิดแท็บผู้ใช้ ใช้คำค้นและตัวกรอง role/กลุ่ม
2. เลือกบัญชีจาก directory ซึ่งแบ่งหน้าละสิบบัญชี
3. ด้านขวาแสดงชื่อ อีเมล role วันสร้างบัญชี จำนวน login และเวลา login ล่าสุด
4. กรอกชื่อ รหัสผู้เข้าร่วม อายุ มือถนัด รหัสรอบ กลุ่ม ระดับการศึกษา คะแนน MMSE และหมายเหตุ
5. กดบันทึกข้อมูล เมื่อสำเร็จข้อมูลในภาพรวมอัปเดตทันที

| ฟิลด์ | ค่าที่รับ |
| --- | --- |
| ชื่อ | ไม่เกิน 80 ตัวอักษร ปล่อยว่างได้ |
| รหัสผู้เข้าร่วม | ไม่เกิน 40 ตัวอักษร ปล่อยว่างได้ |
| อายุ | จำนวนเต็ม 10–120 หรือว่าง |
| มือถนัด | ขวา `Right`, ซ้าย `Left`, หรือยังไม่ระบุ |
| รหัสรอบ | ไม่เกิน 40 ตัวอักษร เป็นข้อมูลโปรไฟล์ ไม่เริ่มบันทึกรอบ EEG |
| กลุ่ม | ผู้ป่วย `patient`, ควบคุม `control`, หรือยังไม่ระบุ |
| การศึกษา | `none`, `primary`, `above`, หรือยังไม่ระบุ |
| หมายเหตุ | ไม่เกิน 2,000 ตัวอักษร รองรับหลายบรรทัด |

แอดมินเพิ่มบัญชีได้ด้วยปุ่ม **เพิ่มผู้ใช้** ใน Dashboard: กรอกชื่อ อีเมล และรหัสผ่านของผู้ใช้ใหม่ (8–200 ตัวอักษร) เลือก role เป็น `user`, `researcher` หรือ `admin` จากนั้นกรอกอีเมลและรหัสผ่านของบัญชีแอดมินที่กำลังเข้าสู่ระบบ แล้วกด **ยืนยันและเพิ่มผู้ใช้** ต้องยืนยันทุกครั้ง แม้ระบบปิดการสมัครสมาชิก แอดมินก็ยังเพิ่มบัญชีได้ บัญชีแอดมินที่เข้าสู่ระบบจะคงเดิม และบัญชีใหม่ต้องเข้าสู่ระบบด้วยข้อมูลของตนเอง นักวิจัยและผู้ใช้ทั่วไปไม่มีสิทธิ์เพิ่มบัญชี

ในฟอร์มแก้ไขข้อมูลผู้เข้าร่วม อีเมลและ role ยังเป็นข้อมูลอ่านอย่างเดียว ไม่มีการเปลี่ยน email หรือรหัสผ่าน

ข้อมูลที่ยังไม่บันทึกจะค้างอยู่เมื่อเปลี่ยนแท็บหรือ background refresh ล้มเหลว เมื่อเปลี่ยนผู้ใช้/โหลดข้อมูลล่าสุด/ยกเลิกการแก้ไข ระบบถามก่อนทิ้ง draft หากได้รับข้อความ “ข้อมูลถูกแก้ไขโดยผู้อื่นแล้ว” ให้จดการแก้ไขที่ต้องการ โหลดข้อมูลล่าสุด ตรวจความเปลี่ยนแปลง และกรอกใหม่ก่อนบันทึก เป็นการป้องกันการเขียนทับจากสองคนหรือสองแท็บ

### 4.3 กรอก MMSE บนโปรไฟล์

ระบบเป็นฟอร์มบันทึกคะแนนด้านต่าง ๆ ให้ใช้ผลจากขั้นตอนประเมินตามโครงการ เลือกระดับการศึกษาก่อนกรอกคะแนน แผง MMSE เปิดแยกจากข้อมูลทั่วไป

| ลำดับใน `mmseScores` | ด้าน | คะแนนสูงสุด |
| --- | --- | --- |
| 0 | การรับรู้เวลา | 5 |
| 1 | การรับรู้สถานที่ | 5 |
| 2 | การบันทึกความจำ | 3 |
| 3 | สมาธิและการคำนวณ | 5 |
| 4 | การระลึกได้ | 3 |
| 5 | การใช้ภาษา | 6 |
| 6 | การอ่านและเขียน | 2 |
| 7 | การสร้างภาพ | 1 |

เมื่อ `education=none` ด้านสมาธิ/คำนวณและอ่าน/เขียนถูกปิดและนับเป็น 0 จึงมีคะแนนเต็ม 23 เมื่อเป็นประถมหรือสูงกว่าประถมคะแนนเต็ม 30 ช่องที่ยังไม่ได้ประเมินเว้นว่างได้และเก็บเป็น `null` ซึ่งต่างจาก 0 คะแนน ผลรวมแสดง “ยังไม่ครบ” จนด้านที่ต้องใช้ครบ

เปลี่ยนการศึกษาเป็น “ยังไม่ระบุ” จะล้างคะแนนใน draft ทั้งหมด เปลี่ยนเป็น `none` จะตั้งสองด้านที่ปิดเป็น 0 ต้องกดบันทึกจึงเปลี่ยนข้อมูลบน server

### 4.4 ผลการทดลอง

แท็บนี้โหลด summary ที่ sync สำเร็จจาก server และมีตัวเลือกบัญชี/ผู้เข้าร่วม ขณะเลือกบัญชี ระบบรวม record ที่ผู้ส่งเป็นอีเมลนั้น **หรือ** participant ID ตรงกับรหัสในโปรไฟล์ จึงอาจรวมข้อมูลจากนักวิจัยหลายคนหากใช้รหัสผู้เข้าร่วมเดียวกัน

ดูวันเวลา รหัสรอบ กลุ่ม เกม protocol สถานะ เวลากิจกรรม จำนวน EEG samples อัตราเฉลี่ย และผลเกมได้ เลือกสอง record ที่ต่างกันเพื่อเปรียบเทียบเวลา samples clipping packet gap และผลเกม ผลต่างคำนวณ “รอบเปรียบเทียบ − รอบอ้างอิง” หาก protocol ต่างกันจะแสดงข้อความให้ตรวจขั้นตอนก่อนตีความ

กด “ส่งออกสรุปทุกครั้ง (.csv)” ได้หนึ่งแถวต่อ record ในชุดข้อมูลที่กำลังแสดง มี `uploaded_by` ระบุผู้ส่ง ตารางนี้ดาวน์โหลด EEG ดิบจาก server ไม่ได้ และไม่ทราบว่ารอบนั้นลบ raw ในเบราว์เซอร์แล้วหรือยัง

### 4.5 ข้อมูลในเครื่อง

แท็บนี้อ่านเฉพาะรอบของบัญชีที่ login ใน IndexedDB ของเบราว์เซอร์ปัจจุบัน มีกราฟ EEG ปฏิทิน ตัวกรองวัน/ช่วงเวลา และสรุปทุกรอบ รายละเอียดใช้เหมือน Dashboard ของบัญชีทั่วไปในหัวข้อถัดไป

## 5. Dashboard ของบัญชีทั่วไปและกราฟ EEG ในเครื่อง

บัญชี `user` ไม่มีแท็บจัดการผู้ใช้รวม แต่เห็น Dashboard การบันทึกของตนเอง เปิดบนอีกเครื่องหรืออีก origin แล้วอาจว่าง เพราะข้อมูลรอบอยู่ในเบราว์เซอร์เดิม

ใช้ช่องค้น รหัสผู้เข้าร่วม/รอบ/กลุ่ม ช่วงทั้งหมด/30 วัน/7 วัน และวันในปฏิทินร่วมกันได้ กดวันที่ซ้ำเพื่อเลิกเลือกหรือใช้ปุ่มล้างตัวกรอง

| ส่วน | ข้อมูลที่ใช้ |
| --- | --- |
| จำนวนรอบ/รหัสผู้เข้าร่วม/สถานะ | รอบในเครื่องของบัญชีนี้ตามตัวกรอง |
| จำนวน sample รวมสำหรับการทดลองครบ | รวมจาก research session ที่ `complete` และไม่ใช่ device test |
| กราฟจำนวน sample สี่ช่อง | รอบวิจัยครบล่าสุดในผลที่กรอง |
| กราฟเวลาแต่ละช่วง | เวลาจริง baseline/task/rest ของรอบครบล่าสุด |
| กราฟอัตรา EEG ตามรอบ | สูงสุดแปดรอบวิจัยครบล่าสุด เรียงเก่าไปใหม่ |
| ผลเกม | รอบครบที่มีผลเกมจริง |
| สัดส่วนสถานะ | รอบครบ รอบวิจัยไม่ครบ และ device test |
| ปฏิทิน | วันที่มีข้อมูลในเครื่องของบัญชีนี้ ใช้กดกรองวัน |
| สรุปผลทุกครั้งที่ทดลอง | ทุกรอบตามตัวกรอง รวมหยุดก่อนครบและ device test |

ยังไม่มีรอบครบจะเห็นหน้าว่าง/คำแนะนำ กราฟไม่เติม sample จำลอง สำหรับรอบเก่าที่ไม่มี summary ระบบพยายามอ่าน marker ใน raw แล้วสร้าง summary เมื่อเปิด Dashboard

ตารางสรุปในเครื่องใช้เปรียบเทียบสองรอบและส่งออก summary CSV ได้ แสดง raw ว่าเก็บอยู่หรือลบแล้ว ส่วนการส่งออก raw/ลบรายการทำในห้องทดลอง EEG

## 6. ห้องทดลอง EEG: ขั้นตอนเก็บข้อมูล

### 6.1 กรอกชุดทดลอง

1. กรอกรหัสผู้เข้าร่วม เช่น `P001` สูงสุด 40 ตัวอักษร
2. กรอกรหัสรอบฐาน เช่น `S01` สูงสุด 37 ตัวอักษร เพื่อเหลือที่สำหรับ `-G1`/`-G2`/`-G3`
3. เลือกกลุ่มผู้ป่วยหรือกลุ่มควบคุม
4. กรอกเงื่อนไข เช่น `standard` สูงสุด 80 ตัวอักษร ใช้ข้อความที่โครงการกำหนดให้สม่ำเสมอ
5. กำหนด Task สูงสุดตั้งแต่ 5 วินาทีถึงค่าสูงสุดที่ admin อนุญาต Baseline และ Rest แสดงค่าจากการตั้งค่า
6. ยืนยันว่าได้รับความยินยอมตามขั้นตอนโครงการ ช่องนี้เป็นการยืนยันของผู้วิจัย ไม่มีระบบลายเซ็น/อัปโหลดเอกสาร consent

เมื่อเริ่มแล้วฟอร์มจะล็อกจนเริ่มชุดใหม่ การกรอกข้อมูลในฟอร์มนี้ไม่เปลี่ยนโปรไฟล์ Dashboard และไม่ต้องทำแบบประเมินเดิมให้เสร็จก่อน

### 6.2 เชื่อม Muse

เลื่อนมาส่วนตรวจสัญญาณสด กด “เชื่อมต่อ Muse” เลือกเครื่อง Muse/MuseS ในหน้าต่าง Bluetooth แล้วกด Pair รอขั้นตอนเลือกเครื่อง → GATT → Muse service → รับ EEG ค่าแต่ละช่องจะขึ้นและสถานะเป็น “EEG ครบ 4 ช่อง”

การเห็นชื่อใน Bluetooth หรือข้อความ Connected ยังไม่พอ ต้องรับข้อมูลต่อเนื่องครบทุกช่อง หากเริ่มไม่ได้ให้ดูข้อความ precheck และอ่าน [ขั้นตอนแก้ปัญหา Muse](troubleshooting.th.md)

กราฟสดปรับศูนย์และสเกลเพื่ออ่านง่าย เลข µV ใหญ่สี่ช่องเป็น sample ล่าสุด ไม่ใช่คะแนน เกม/ความจำ ค่า 50 Hz เป็นการตรวจรบกวนเบื้องต้น การแสดงผลไม่เปลี่ยนค่า raw ที่บันทึก

### 6.3 ทดสอบอุปกรณ์ 15 วินาที

กดทดสอบจากสถานะเตรียมรอบ ระบบยังต้องเชื่อมครบสี่ช่อง มี IndexedDB และตรวจ config จาก server ได้ แต่ไม่ต้องกรอก participant/consent หรือผ่าน precheck clipping แบบรอบวิจัย บันทึกช่วงละ 5 วินาที รวม 15 วินาที ไม่มีเกมจริง ใช้ `participant=TEST`, `gameId=0`, `testMode=true`, protocol `device_check_v1`

เมื่อจบส่งออกไฟล์ ตรวจคุณภาพ และกดเริ่มรอบใหม่ก่อนชุดวิจัย Device test มี summary และ sync ได้ แต่ไม่รวมในกราฟรอบวิจัยครบ

### 6.4 ทำสามเกมตามลำดับ

1. เมื่อพร้อมกด “เริ่มชุดทดลอง · เกม 1” ระบบสร้าง sequence และ record เกม 1
2. Baseline เริ่มรับ EEG อัตโนมัติ ให้นั่งพักนิ่งตามโครงการ
3. เมื่อครบ Baseline เกม Odd or Even เริ่มเองในหน้าเกมพร้อม marker และตัวจับเวลา Task
4. กด “Next · จบเกมและบันทึกช่วงพัก” เมื่อจบกิจกรรม หรือรอ Task ครบเวลาสูงสุด ระบบหยุดเกมและรับ EEG ต่อใน Rest
5. รอ Rest จบและการบันทึกลงเครื่องสำเร็จ จากนั้น “Next · เริ่มเกม 2” จึงเปิดใช้
6. ทำเกม Echo Sequence และ Pattern Drift แบบเดียวกัน แต่ละเกมมี Baseline/Task/Rest ของตัวเอง
7. เมื่อเกม 3 ครบ กดดูผลทั้งสามเกม หรือส่งออก EEG แต่ละเกมจากรายการรอบในเครื่อง

Next ระหว่าง Task คือจบกิจกรรมและเข้า Rest; Next หลังบันทึกครบคือเริ่ม Baseline ของเกมถัดไป ไม่ใช่การข้าม Rest สามเกมไม่ได้ต่อ raw เป็นไฟล์เดียว และเวลารวมสูงสุด 600 วินาทีใช้ต่อรอบหนึ่งเกม ไม่ใช่รวมทั้งชุด

รอบไม่ครบต้องลองเกมเดิมใหม่ก่อนเดินต่อ การ retry คง sequence และชื่อรอบเกม เช่น `S01-G2` แต่สร้าง record UUID ใหม่ เก็บรอบเก่าที่ไม่ครบไว้ด้วย ไม่มีการเขียน raw เดิมทับ

### 6.5 Marker และหยุดรอบ

ระหว่างบันทึกใช้ช่อง marker เพื่อเพิ่มเหตุการณ์นอกเกมตามรหัสที่โครงการกำหนด ระบบใส่ marker เริ่ม/จบ phase และสิ่งเร้า/ตอบเกมอัตโนมัติ

“หยุดและเก็บข้อมูล” สิ้นสุดรอบเป็น `stopped` และเก็บส่วนที่รับได้ ส่วน disconnect, ช่องใดหายเกินสามวินาที, ซ่อนแท็บ, ออกจากหน้าเกมระหว่าง Task หรือเกมไม่เริ่ม ทำให้หยุดเป็นสถานะเฉพาะ ห้ามนำรอบเหล่านี้ไปนับว่า complete เพียงเพราะมี CSV

### 6.6 ส่งออก ลบ raw และลบรายการ

รายการ “รอบทดลองที่เก็บในเครื่อง” มีปุ่มดูสรุป ส่งออก CSV ลบ EEG ดิบเก็บสรุป และลบรอบถาวร

- ส่งออกได้เมื่อรอบหยุดแล้วและยังมี raw ระบบสั่ง browser ดาวน์โหลดไฟล์ ต้องเปิดไฟล์ตรวจใน Downloads เอง ค่า exported บอกว่าเคยสั่งดาวน์โหลด ไม่ใช่การยืนยันว่าไฟล์ถูกสำรองแล้ว
- ลบ EEG ดิบเก็บสรุปเปิดให้ใช้หลัง exported และถามยืนยัน ลบ chunks ทำให้ส่งออก raw อีกไม่ได้ แต่ยังเทียบ summary ได้
- ลบรอบถาวรถามยืนยันและลบเฉพาะ IndexedDB ของเครื่องนี้ ปุ่มปิดสำหรับรอบที่ยัง recording และรอบปัจจุบัน ให้เริ่มชุด/รอบใหม่ก่อนลบรายการปัจจุบัน
- การเริ่มชุดใหม่ไม่ลบรอบเก่าที่บันทึกเสร็จไว้ ข้อมูลยังอยู่ในรายการ

## 7. ภารกิจการรู้คิดและโหมดฝึก

นอกการบันทึกเปิด “ฝึกเกมก่อนเริ่ม · ไม่บันทึก EEG” แล้วเลือกเกมได้ ฝึกเพื่อทำความเข้าใจปุ่ม มีตัวชี้วัดบนจอ แต่ไม่สร้างรอบ EEG/summary ฝึกใน IndexedDB เกมจริงเริ่มจากชุดทดลองในห้องทดลอง

| เกม | วิธีตอบ | เวลาเริ่มนับ RT |
| --- | --- | --- |
| Odd or Even | ตัวเลขสุ่ม 1–9 กดคี่หรือคู่ | หลังแสดงสิ่งเร้าและเปิดรับคำตอบ |
| Echo Sequence | จำเลขสี่ตัว 1–6 ที่แสดง 2.2 วินาที แล้วกรอกลำดับเดิม; ช่องว่างถูกตัด | เมื่อขึ้น prompt ให้ตอบหลังช่วงแสดงลำดับ |
| Pattern Drift | เทียบสองแถวรูปสัญลักษณ์ กดเปลี่ยน/เหมือนเดิม | หลังแสดงสิ่งเร้าและเปิดรับคำตอบ |

รับหนึ่งคำตอบต่อ trial กดซ้ำไม่เพิ่มคะแนน รอรอบถัดไป 250/400/300 ms ตามเกม Accuracy = ตอบถูก/จำนวนคำตอบ × 100; Reaction time = ค่าเฉลี่ย RT; Errors = คำตอบผิด; Variability = SD ของ RT บนหน้าจอเมื่อมีมากกว่าหนึ่งคำตอบ

Task ไม่มีจำนวน trial ตายตัว จบเมื่อกดจบหรือเวลาเต็ม สิ่งเร้าที่ถูกตัดก่อนตอบไม่นับเป็นคำตอบผิดใน summary เกม ใช้ raw marker และ validator ตรวจ unanswered trials เพิ่มเมื่อต้องวิเคราะห์เรื่องนี้

## 8. เครื่องมือประเมินเดิมและประวัติแบบประเมิน

ในห้องทดลองเปิดส่วนยุบ “เครื่องมือประเมินเดิม” ใช้ลำดับดังนี้: โปรไฟล์ในเครื่อง → MMSE → เกม Context Switch Trail → Echo Sequence → Pattern Drift → สรุปผล เป็น workflow คนละชุดกับ EEG sequence หลัก

โปรไฟล์เดิมเก็บรหัส อายุ มือถนัด และรอบ MMSE บันทึกคะแนนด้านต่าง ๆ คำนวณคะแนนเต็มและจุดตัดตามค่าที่มีในโค้ด เกมเดิมมีหก trial ต่อเกม; Context Switch สลับกฎคี่/คู่กับต่ำ/สูง และ Echo เพิ่มความยาวลำดับเป็น 4/5/6 ตัวตาม trial จึงไม่ใช่เกม Odd or Even และ Echo สี่ตัวของโหมดวิจัยหลัก

| ระดับการศึกษาในเครื่องมือเดิม | คะแนนเต็ม | จุดตัดที่โค้ดใช้ |
| --- | --- | --- |
| `none` | 23 | ≤14 |
| `primary` | 30 | ≤17 |
| `above` | 30 | ≤22 |

ตารางนี้อธิบายค่าที่ implementation ใช้ ไม่ใช่คำแนะนำการวินิจฉัยหรือการรับรองเกณฑ์ทางคลินิก หน้าเดิมแสดงสีแดงเมื่อคะแนน ≤จุดตัด สีเหลืองเมื่อสูงกว่าจุดตัดไม่เกินสามคะแนน และสีเขียวเมื่อมากกว่านั้น สีเป็นวิธีสื่อสารในแอป ผลเกมไม่เปลี่ยนสี MMSE

เมื่อทำครบระบบเก็บประวัติใน `cogni_assessments_<email>` เปิดเมนูประวัติแบบประเมินเพื่อดู และกด Export CSV ได้ `CogniLoad_assessment_export.csv` รวมคะแนน MMSE ผลเกมเดิม และสรุป baseline เดิมถ้ามี ปุ่ม “เริ่มการประเมินใหม่” ที่หน้าสรุปเริ่ม Journey ใหม่โดยยังเก็บประวัติครั้งก่อน

ประวัตินี้ไม่ sync Neon และไม่ถูกนำเข้าช่องโปรไฟล์ Dashboard อัตโนมัติ ตัวนับ login เดิมใน localStorage ก็แยกจาก `login_count` ฝั่ง server ตัวนับในเครื่องจำสูงสุด 100 เหตุการณ์และ Dashboard เดิมแสดงห้าล่าสุด

โค้ด baseline เดี่ยว 30 วินาทีสำหรับเครื่องมือเดิมยังอยู่ แต่ปุ่ม/ผลส่วนนี้ถูกซ่อนด้วย CSS การเก็บ EEG ในการใช้งานปัจจุบันให้ใช้ ResearchSession ที่บันทึกครบ baseline/task/rest

## 9. หน้า Admin

### ตั้งค่ารอบทดลอง

Admin เปิดเมนูผู้ดูแลระบบ กรอก Baseline, Rest, Task สูงสุด, Task ค่าเริ่มต้น และรหัส protocol แล้วบันทึก ป้าย “ค่าจากหน้าเว็บ” หมายถึงมีค่าที่บันทึกถาวรซึ่งมีลำดับก่อน environment defaults

Baseline/Rest เป็นจำนวนเต็ม 1–300 วินาที แต่ต้องเหลือเวลา Task อย่างน้อยห้าวินาทีภายใน 600 วินาที Task สูงสุด ≤ `600 − Baseline − Rest` และ Task ค่าเริ่มต้น ≤ Task สูงสุด protocol ยาว 1–64 ใช้ตัวอักษรอังกฤษ ตัวเลข จุด ขีดล่าง ขีดกลาง และเริ่มด้วยตัวอักษรหรือตัวเลข

บันทึกมีผลกับรอบใหม่ รอบที่กำลัง recording ใช้ค่าเริ่มต้นของรอบนั้น เกมถัดไปใน sequence ตรวจ config อีกครั้ง จึงควรหลีกเลี่ยงเปลี่ยนโปรโตคอลระหว่างเก็บชุดเดียวกัน หากจะกลับ environment defaults กดคืนค่าเซิร์ฟเวอร์และยืนยัน

### ดูสรุปรายรหัสผู้เข้าร่วม

ค้นเช่น `P001` กดรหัสในรายการเพื่อเปิดทุก summary ที่ sync แล้วจากผู้ส่งทุกบัญชี มีจำนวนรอบ ผู้ส่ง ตาราง เปรียบเทียบ และ CSV รอบวิจัยไม่ครบ/device test อาจปรากฏด้วย รายการนี้สร้างจาก summary ไม่ใช่ทะเบียนบัญชี จึงยังไม่พบผู้เข้าร่วมที่มีเพียงโปรไฟล์แต่ไม่เคย sync รอบ

## 10. ออกจากระบบและกลับมาทำต่อ

กด logout บนแถบบน ระบบตัด Muse ลบ session cookie และข้อมูลตัวตนใน sessionStorage แต่ไม่ลบ IndexedDB/localStorage หากมีข้อมูลรอบที่ยังอยู่ในแท็บระบบอาจถามยืนยันก่อนออก ให้ส่งออก/ตรวจการบันทึกให้เสร็จก่อน

กลับมา login ด้วยบัญชีเดิมและเปิด origin/browser profile เดิม สามารถพบรอบก่อน ถ้าปิดระหว่างบันทึก รอบล่าสุดที่กู้ได้เปลี่ยนเป็น `interrupted` ใช้เวลา packet ล่าสุด ชุดสามเกมที่กู้ได้ให้ reconnect Muse แล้วใช้ retry/Next ตามรายการที่บันทึกสำเร็จ ไม่ต่อ raw จากจุดกลางของรอบเดิม

ปุ่มติดตั้งแอปแสดงเมื่อ browser ส่ง install prompt เท่านั้น Manifest ปัจจุบันไม่มีชุด icon สำหรับติดตั้งครบทุกแพลตฟอร์ม จึงไม่รับรองว่าปุ่มติดตั้งจะมีทุกเครื่อง การติดตั้งไม่ได้เพิ่ม offline backend หรือย้ายข้อมูลออกจาก browser profile
